Короткий опис роботи
--------------------
Mini Issue Tracker — навчальний UX/UI-проєкт внутрішнього вебзастосунку для керування задачами та помилками команди розробників.

У межах роботи ми проаналізували специфікацію S1, визначили вимоги MVP, створили карту екранів, контракти та інтерактивний прототип у Figma.

Проєкт виконували спільно Григорій Зінченко та Тимофій Кадигроб. Обидва учасники брали участь в усіх етапах розробки, перевірки та виправлення макета.

Ключові результати
------------------
- Опрацьовано 8 User Stories та 33 Acceptance Criteria.
- Створено Input Pack, Screen Map і Screen Contracts.
- Погоджено UX/UI-рішення D-01–D-09.
- Створено редагований low-fidelity макет у Figma.
- Реалізовано демонстраційну навігацію між All, Important, Create Issue та Issue Details.
- Підготовлено приклади призначення відповідального та зміни пріоритету.
- Показано чотири дозволені переходи статусів.
- Створено приклади коментарів, помилок і порожніх станів.
- Перевірено основні сценарії прототипу.
- Виправлено виявлені проблеми в макеті.
- Підготовлено Review Report, Defect / Change Log та AI Interaction Log.

Межі перевірки
--------------
- Робота охоплює UX/UI-дизайн і демонстраційний прототип, а не повноцінний вебзастосунок.
- Основні екрани перевірено за скриншотами.
- Основні переходи перевірено командою у Figma Present.
- Валідація полів представлена статичними прикладами.
- Реальне збереження даних не реалізовано.
- Динамічне оновлення списку Important не реалізовано.
- Backend, база даних та авторизація користувачів не реалізовані.
- Серверні перевірки прав, HTTPS, резервне копіювання та продуктивність не тестувалися.
- Частина Acceptance Criteria потребує перевірки після програмної реалізації.
- Незалежний Control B було пропущено; його не позначено як пройдений.
- Результати перевірок і залишкові обмеження описано у P1_Prototype_Test_Record.md та 06_Review_Report.md.
