**Файл:** `01_Input_Pack_v1.0.md`  
**Версія:** v1.0  
**Статус:** НА ПЕРЕВІРЦІ — контроль A виконаний, але документ **НЕ ЗАТВЕРДЖЕНО** (погоджено тільки D-01).  
**Джерело:** `SD_Spec.docx.pdf` (S1), 13 сторінок, усі розділи §0–§9.  
**Призначення:** перевірена вибірка вимог для UX/UI. У цьому документі вимоги джерела відокремлені від UX-рішень.

## 0. Правила джерел і позначення

**SOURCE** — вимога вихідної специфікації S1; **DERIVED** — обґрунтований висновок із неї; **PROPOSED** — запропоноване, але не обов'язкове рішення; **UNRESOLVED** — потребує людського рішення.

Доступні: §0 — запит замовника; §1 — аналіз проблеми; §2 — бачення й обсяг продукту; §3 — вимоги зацікавлених сторін та бізнес-правила; §4 — попередня пріоритизація; §5 — історії користувачів та критерії приймання; §6 — якісні й безпекові вимоги; §7 — здійсненність і ризики; §8 — остаточний MVP та оновлені NFR; §9 — заголовок розділу UX/UI, без додаткових детальних вимог.

Остаточний склад першого релізу визначає **S1 §8**, а не попередній Candidate MVP §4. Це не означає, що §8 автоматично скасовує всі попередні бізнес-правила: їхні суперечності слід фіксувати окремо.

## 1. Мета, актори, межі релізу

**SOURCE — S1 §1–§2.** Mini Issue Tracker — внутрішній вебзастосунок для невеликої команди розробників. Він призначений для реєстрації, перегляду й відстеження проблем, призначення відповідальних, установлення пріоритетів та обговорення проблем. Також він допомагає знаходити важливі незакриті issues.

| Актор | Можливості | Джерело |
|---|---|---|
| Team Member | Створення, перегляд і коментування issue; зміна status лише якщо користувач — поточний assignee | S1 §1; BR-01/02/08; US-01/02/05/06/07 |
| Team Lead | Усі загальні дії; додатково призначення assignee та зміна priority; зміна status тільки якщо сам є assignee | S1 §1, BR-06/08, US-03/04, AC-07.4 |

За BR-01 у першій версії три наперед визначені користувачі: два Team Member та один Team Lead. Product Owner і System Administrator — другорядні зацікавлені особи, не додаткові ролі основних сценаріїв (S1 §1).

**Release MVP — SOURCE, S1 §8:** включено US-01–US-08.

| ID | Назва українською | Суть |
|---|---|---|
| US-01 | Створити issue | Зареєструвати назву й опис |
| US-02 | Переглянути issues | Список і деталі |
| US-03 | Призначити assignee | Визначити відповідального |
| US-04 | Установити priority | Визначити пріоритет |
| US-05 | Відстежувати прогрес | Бачити поточний status |
| US-06 | Додати коментар | Обговорювати issue |
| US-07 | Оновити статус | Змінювати status за правилами |
| US-08 | Переглянути важливі незакриті issues | Відбір High/Critical, які не Closed |

**Deferred — відкладено:** US-09 — прикріплення файлів (S1 §7–§8). Вимоги до file storage, file size, malware scanning та backup вкладень не входять до першого релізу.

**Future — майбутнє:** SR-10 — автоматична категоризація issue; SR-11 — рекомендації priority (S1 §3–§4, §8). За BR-12 навіть у майбутній реалізації AI не змінює category/priority без дії користувача.

**Поза обсягом:** портал підтримки клієнтів, billing, розміщення вихідного коду, CI/CD, облік часу, повне керування проєктами, мобільний застосунок, інтеграція з GitHub/GitLab/Jira, видалення issue (BR-10), окрема користувацька історія змін (BR-11), US-09 та AI-функції в першому релізі (S1 §1–§3, §8).

**DERIVED — S1 §8:** не створювати UI для Deferred/Future як частини MVP.

### 3.1 Матриця переходів status

| Поточний status | Open | In Progress | Resolved | Closed |
|---|---|---|---|---|
| Open | Поточний | **Дозволено** | Заборонено | Заборонено |
| In Progress | Заборонено | Поточний | **Дозволено** | Заборонено |
| Resolved | Заборонено | **Дозволено** | Поточний | **Дозволено** |
| Closed | Заборонено | Заборонено | Заборонено | Поточний |

Поточне значення не є переходом. Terminal Closed стосується лише зміни status: це не є підставою автоматично забороняти коментарі або зміну priority (DERIVED — BR-08.1).

### 3.2 Відбір Important Issues

**DERIVED — BR-09/09.1, AC-08.1–08.4:**  
`(priority = High OR priority = Critical) AND status != Closed`

High/Open, Critical/In Progress, High/Resolved і Critical/Resolved включені. Будь-який Closed, будь-який Low/Normal та Not Set виключені.

### 3.3 Заборони

**SOURCE — S1 §3/§5/§8:** Member не призначає assignee й не змінює priority; статус змінює тільки assignee; інші status transitions не виконуються; порожній comment не додається; невдала спроба збереження не створює comment; видалення, change history, attachments та AI — не частина поточного MVP.
